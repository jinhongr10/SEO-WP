# 页面计划 Tab 设计文档

日期：2026-05-12

## 背景

当前工具已经包含博客写作、产品 SEO、媒体库 SEO 压缩、WordPress 草稿同步和博客内链优化能力。新的需求是新增一个独立的“页面计划”工作区，用于根据大量产品相关关键词生成固定页面规划，帮助后续人工在 Elementor 中制作页面。

这个功能不直接生成 Elementor HTML，也不批量发布页面。第一版只生成页面计划、内容大纲和内链建议，避免 AI 产出的 HTML 与 Elementor 结构不兼容。

## 目标

- 从 Excel/CSV 或已有关键词库导入关键词。
- 根据关键词自动聚类，形成可执行的固定页面计划。
- 为每个页面生成标题、SEO 标题、URL slug、关键词组、页面类型、搜索意图和优先级。
- 为每个页面生成 Elementor 人工搭建用的大纲，而不是完整正文。
- 为每个页面推荐内部链接，包括产品页、分类页、已有页面、已有博客和页面计划之间的互链。
- 支持人工编辑、复制和导出计划，方便后续执行。

## 非目标

- 第一版不生成完整页面正文。
- 第一版不生成 Elementor HTML、短代码或区块模板。
- 第一版不自动创建 WordPress 页面。
- 第一版不自动发布页面。
- 第一版不做搜索量、KD、CPC 等外部 SEO 数据抓取，除非后续接入 Semrush 或其他数据源。

## 用户流程

1. 用户打开顶部导航中的“页面计划” tab。
2. 用户上传关键词 Excel/CSV，或选择现有关键词库。
3. 用户补充页面规划参数：
   - 目标产品类别
   - 目标市场或买家类型
   - 页面数量上限
   - 语言和页面风格
4. 点击“生成页面计划”。
5. 后端读取关键词、公司背景、产品缓存和 WordPress 已有内容，调用 AI 生成页面计划。
6. 前端展示页面计划表，每行代表一个建议页面。
7. 用户点开单页详情，查看内容大纲和内链建议。
8. 用户可编辑字段、复制单页计划、导出 CSV/JSON，或后续进入人工 Elementor 制作流程。

## 页面类型

AI 自动将关键词聚类为以下类型：

- 产品类目页：围绕产品大类或子类，例如 product sample、travel fan。
- 应用场景页：围绕使用场景，例如 enterprise deployment site supplies、institution hand maintenance。
- 解决方案页：围绕买家问题或采购需求，例如 deployment site maintenance solution。
- 材质/功能页：围绕材料、安装方式、容量、感应方式等属性。
- 安装/采购指南页：围绕选择、安装、批发采购、维护等问题。

## 页面计划字段

每个页面计划包含：

- pageTitle：页面标题
- seoTitle：SEO Title，建议不超过 60 字符
- slug：URL slug
- primaryKeyword：主关键词
- secondaryKeywords：辅助关键词列表
- pageType：页面类型
- searchIntent：搜索意图
- priority：优先级，高/中/低
- relatedProducts：推荐关联产品
- relatedCategories：推荐关联分类
- outline：内容大纲
- internalLinks：内链建议
- notes：人工执行备注

## 内容大纲结构

每个页面的大纲用于指导 Elementor 人工搭建，包含：

- Hero 标题
- Hero 副标题
- Section 列表
  - H2/H3 标题
  - 本 section 应该说明的内容
  - 建议使用的产品、图片、证书、工厂信息或对比模块
- FAQ 问题列表
- CTA 建议

大纲要求每个页面有独立搜索意图，避免多个页面只是替换关键词的重复内容。

## 内链建议

每个页面生成以下内链建议：

- 链接到相关产品页。
- 链接到相关产品分类页。
- 链接到已有 WordPress 固定页面。
- 链接到已有博客文章。
- 链接到本次页面计划中的其他相关页面。
- 为每个链接提供推荐锚文本和链接理由。

第一版只输出建议，不自动写入 WordPress 内容。

## 架构

### 前端

在 `App.tsx` 的 `viewMode` 中新增 `pagePlanner` 模式，并在顶部导航增加“页面计划”按钮。

建议拆出组件：

- `components/PagePlannerDashboard.tsx`
  - 管理页面计划 tab 的主要 UI。
  - 包含关键词导入、参数表单、结果表格、详情面板和导出按钮。

新增服务文件：

- `services/pagePlannerService.ts`
  - 调用后端页面计划接口。
  - 定义前端使用的请求和响应类型。

### 后端

在 `backend/main.py` 增加页面计划接口：

- `POST /page-planner/generate`
  - 输入关键词文本、页面数量上限、目标产品类别、目标市场、公司背景开关等。
  - 输出页面计划数组、整体统计和警告信息。

可复用现有能力：

- `_build_company_prompt`
- `_blog_link_candidates`
- `_blog_rank_candidates`
- 产品缓存表 `product_items`
- WordPress pages/posts/products/categories 拉取逻辑
- 现有 Gemini/Vertex AI 配置和 JSON 解析工具

### 数据流

1. 前端解析 Excel/CSV 为关键词文本，或加载已有关键词库。
2. 前端提交关键词文本和规划参数到后端。
3. 后端聚合上下文：
   - 关键词文本
   - 公司背景
   - 产品缓存
   - WordPress 已有页面/博客/产品/分类候选
4. 后端调用 AI 生成结构化 JSON 页面计划。
5. 后端对结果做规范化：
   - slug 清洗
   - SEO title 长度限制提示
   - 页面类型校验
   - 内链 URL 去重
6. 前端渲染计划表和详情面板。
7. 用户编辑、复制或导出。

## 错误处理

- 未配置 AI：提示用户到系统配置中检查 Gemini 或 Vertex AI。
- 关键词为空：前端禁止提交，后端返回 400。
- AI 返回非 JSON：后端尝试解析；失败时返回清晰错误。
- WordPress 候选拉取失败：不中断页面计划生成，但返回 warnings。
- 产品缓存为空：仍可生成计划，但降低关联产品建议质量，并显示提示。
- 页面数量过大：后端限制第一版最多 50 页，避免一次性生成不可控结果。

## 测试计划

- 后端单元测试：
  - slug 清洗和去重。
  - 页面计划 JSON 规范化。
  - 内链建议去重。
  - 关键词为空时返回错误。
- 前端构建验证：
  - `npm run build`
- 端到端手动验证：
  - 上传关键词 CSV。
  - 生成 5-10 个页面计划。
  - 检查每页是否有标题、slug、关键词、大纲和内链建议。
  - 检查导出内容可用于人工 Elementor 制作。

## 第一版验收标准

- 顶部导航出现独立“页面计划” tab。
- 用户可以导入关键词或粘贴关键词。
- 用户可以设置页面数量上限和目标产品类别。
- 点击生成后返回页面计划表。
- 每个计划页面都有页面标题、SEO title、slug、主关键词、辅助关键词、页面类型、搜索意图和优先级。
- 每个计划页面都有 Elementor 人工搭建用的大纲。
- 每个计划页面都有内链建议和锚文本。
- 不创建、不发布、不覆盖任何 WordPress 页面。

## 后续扩展

- 一键创建 WordPress 空白草稿页，只写入标题、slug 和 SEO 信息。
- 接入 Semrush 或其他关键词数据源，加入搜索量和难度。
- 保存页面计划到本地 SQLite，支持复查和状态管理。
- 增加“已执行/未执行/待修改”状态。
- 增加页面重复度检测，避免过多相似页面。
