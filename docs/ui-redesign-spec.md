# 独立站 AI 极简科技风 UI 规范

> 历史视觉方向：本文件记录早期页面与风格决策。当前可执行的布局、排版、溢出和验收标准以 [`design-system/MASTER.md`](../design-system/MASTER.md) 为唯一依据。

## 设计目标

这个 app 是高频运营工具，不需要“好看的装饰”，需要冷静、直接、快速定位。视觉方向改为极简科技风：黑白灰为主，冷蓝只用于 AI、选中和关键状态，界面靠网格、线条、字号层级和留白建立质感。

核心原则：

- 每个界面都围绕一个工作流组织，不围绕技术模块堆按钮。
- 一级导航保持稳定，二级任务用标签或分段控件，避免隐藏关键操作。
- 所有生成型操作都必须有“输入材料、生成草稿、人工审核、同步发布”的状态线。
- 列表型界面采用“左侧任务池 / 中间表格 / 右侧详情或审核抽屉”的主从结构。
- 高风险动作，如发布、写回 WordPress、批量同步，统一放在固定位置，颜色克制，不用大面积警告色。
- 不使用渐变大背景、彩色卡片、装饰插画、过重阴影和多种主题色。

## 全局布局

### 桌面壳

保持左侧固定导航，但视觉更轻、更直接：

- 左侧 272px rail：品牌、客户站点、一级导航、连接状态、设置。
- 顶部 56px command bar：当前工作区标题、客户档案、全局搜索/快捷任务、刷新。
- 主内容区域：宽屏最大 1440px，复杂工具允许全宽。
- 底部快捷任务输入保留，但改为命令输入框，支持关键词、URL、产品 ID、媒体 ID。

推荐视觉：

- 背景：`#F7F9FC`
- 侧边栏：`#0B0F14`
- 主文字：`#0B0F14`
- 次文字：`#667085`
- 卡片：`#FFFFFF`
- 边框：`#D8E0EA`
- 主操作：`#111827`
- AI / 选中：`#0096FF`
- 成功：`#00A878`
- 警告：`#D97706`
- 危险：`#DC2626`
- 圆角：8px
- 阴影：默认不用；浮层使用极轻阴影 `0 16px 40px rgba(15, 23, 42, 0.10)`。
- 线条：1px，分区靠边框和间距，不靠彩色背景。
- 字号：页面标题 18-20px，面板标题 13-14px，表格 12-13px，辅助信息 11-12px。

## 界面逐页设计

### 1. 首次配置 Setup Wizard

目标：用户第一次打开时知道“还差什么才能进工作台”。

布局：

- 左侧黑色进度栏：AI、WordPress、WooCommerce、SFTP、知识库、SEO 插件检测。
- 右侧表单按模块折叠，每个模块只显示必要字段。
- 顶部固定操作：进入未配置模式、保存并检查、进入工作台。
- 检查结果用状态芯片，不放长段解释。

改进点：

- 把 AI Provider 切换放在模块标题右侧。
- Secret 字段统一显示“已保存 / 可替换”的状态。
- SEO 插件检测做成单独检查卡，显示 detected plugin、write mode、title key、description key。

### 2. 设置弹窗

目标：后期维护配置，不打断当前工作。

布局：

- 左侧设置目录：外观、客户档案、AI、WordPress、WooCommerce、自动扫描、SFTP。
- 右侧当前设置组。
- 底部固定保存栏。

改进点：

- 长表单拆成 tab，不再纵向滚动 7 组内容。
- 客户档案放到第一屏，方便多客户切换。
- AI 测试和 WordPress 检测放在各模块标题右侧。

### 3. 中控台 Command Center

目标：每天先看风险和待办，不需要先想进哪个模块。

布局：

- 顶部健康总览：站点分数、紧急问题、警告、已生成未同步、待审核。
- 第二行：今日动作、客户上下文、后台任务状态。
- 中部：SEO Gap 搜索和每日 SEO 队列。
- 底部：优先处理队列，支持内容类型、严重程度、问题类型筛选。

改进点：

- 把“下一步动作”作为每条 issue 的主按钮。
- 分数卡旁增加“本次最该做的 3 件事”，用简洁列表，不做彩色大卡。
- Daily queue 用时间线显示 queued、running、draft generated、synced。

### 4. 客户资料 / Skills

目标：把客户资料沉淀成可复用的 AI 上下文。

布局：

- 顶部客户档案摘要：站点 URL、当前 Skill Pack、资料覆盖度。
- 左侧资料上传和类型卡：公司、产品、关键词、通用。
- 右侧 Skill Pack 版本列表。
- 下方四个预览窗：公司 Skill、产品 Skill、关键词 Skill、任务复用 Skill。

改进点：

- 资料类型卡显示数量和最近更新时间。
- Skill Pack 版本用发布状态和“当前”标记。
- 上传区改成拖放卡，并显示支持格式。

### 5. SEO Audit

目标：把外部审计表变成可审核、可生成、可写回的任务池。

布局：

- 顶部：文件导入卡和导入预览卡并排。
- 任务筛选条固定在任务列表上方。
- 主区：左侧任务表，右侧当前任务详情和生成结果。
- 右侧详情包含 URL、推荐、优先级、生成内容、审核状态。

改进点：

- P0/P1/P2/P3 使用明确优先级色，不只依赖文字。
- “Gemini 生成”移动到右侧详情主操作，列表只保留轻量操作。
- Generated Panel 做 diff 风格：原建议、生成草稿、写回字段。

### 6. 图片处理

目标：本地图片压缩、SEO 生成、上传 WP 形成单图/批量流水线。

布局：

- 左侧大预览：原图/处理后对比，底部缩略队列。
- 右侧三段：批量处理、处理配置、SEO 信息。
- 顶部或右侧显示运行 toast，不遮挡编辑区。

改进点：

- 批量关键词和字段选择放入一个“Batch Bar”。
- SEO 信息字段保留字符计数和复制按钮。
- 已上传 WP 后显示明确链接和媒体 ID。
- 预览区域使用中性棋盘格和细边框，不使用大面积蓝色/绿色面板。

### 7. 媒体库 SEO 压缩

目标：扫描 WordPress 媒体库，生成 SEO 草稿，审核后同步。

布局：

- 顶部状态卡：总媒体、节省空间、失败、已优化、后台状态。
- 操作区分三组：扫描与筛选、AI 生成、发布同步。
- 主表格显示缩略图、文件名、问题标签、状态、更新时间。
- 审核面板使用抽屉或独立区域，左右对比 Original / Generated。

改进点：

- “AI 生成预览”、“加入生成队列”、“直接同步上线”、“仅更新 SEO”分组，不混在一行。
- 字段选择改成 compact checklist，默认全选，状态清楚。
- 审核面板增加字段字符限制进度条和批量批准入口。
- 表格只保留一个冷蓝选中态；问题标签使用低饱和文字芯片。

### 8. 博客写作

目标：从主题和资料开始写作，到 SEO、内链、WordPress 发布闭环。

布局：

- 顶部知识库条：公司背景、产品类目关键词、手动关键词。
- 主区两栏：左侧材料和大纲，右侧正文编辑与发布检查。
- 重写现有博客作为一个折叠工作流，不和新写作平级展开。
- 发布前优化区使用“检查结果 + 预览”双栏。

改进点：

- 当前分步标题保留，但减少大卡嵌套。
- 正文编辑器顶部固定工具条：DOCX、复制、润色、重置。
- 发布按钮只放在发布区，不在写作区重复出现。

### 9. 展会 / 证书 / 项目 / 视频 Blog

目标：基于事实材料生成结构化 Blog 草稿。

布局：

- 顶部文章类型分段控件。
- 左侧事实表单和图片库，右侧生成流程、结果、预览。
- 证书模式突出人工确认，未确认时保存草稿禁用。
- 视频模式把 YouTube 抓取结果做成预览卡。

改进点：

- 图片区改为 media picker，展示用途、Alt、Caption、插入位置。
- Outline 和生成结果上下分离，避免结果字段挤在同一卡片。
- 预览 iframe 保持右侧 sticky，方便边看边改。

### 10. 批量修复 Blog 格式

目标：扫描历史文章，生成预览，确认后写回。

布局：

- 顶部过滤和操作条：状态、Blog 类型、修复模式、问题筛选、搜索、扫描、预览、写回。
- 左侧文章列表，包含 issue badges、核心关键词和摘要指标。
- 右侧文章详情和预览结果。
- Preview 卡按模式切换：格式修复、SEO/Tags/Schema、内容扩写。

改进点：

- SEO 模式下核心关键词输入固定在文章卡内，同时支持批量映射。
- 内容扩写拆成“框架已生成”和“正文已生成”两个状态。
- 写回按钮只在有可写回预览时高亮。

### 11. 页面计划

目标：把关键词库生成可执行页面施工图。

布局：

- 顶部分段控件：页面生成、页面 SEO。
- 输入区：关键词来源、目标类目、买家、页面数量、语言、页面风格。
- 生成结果：左侧页面计划表，右侧所选页面详情。
- 历史记录作为 modal，支持恢复和删除。

改进点：

- 后台任务状态固定显示，不依赖 toast。
- 页面详情顶部显示 SEO Title、Meta、Slug 和导出/复制。
- 大纲模块用 H1/H2/H3 层级树展示，内链建议用列表卡。

### 12. WooCommerce 产品 SEO

目标：产品列表、字段生成、参考图、审核发布形成完整生产线。

布局：

- 顶部状态卡：总产品、当前页、已选择、待审核、扫描缓存。
- 工具条分三组：扫描筛选、字段选择与关键词、AI 生成/队列/同步。
- 主区采用表格 + 右侧详情抽屉。当前展开行过长，建议迁移为详情抽屉。
- 审核面板独立于列表，支持批量批准并同步。

改进点：

- 产品详情拆为 tabs：内容、SEO、参考图、历史。
- Short Description 和 Description 同屏可视化预览。
- 参考图管理沿用媒体库 picker 的视觉模式。
- 不再用展开行承载全部内容；右侧详情抽屉更符合极简工作台。

### 13. 页面 SEO

目标：单页 SEO 检查和修复。

布局：

- 输入 URL 或页面 ID。
- 左侧检测结果和字段现状。
- 右侧建议、生成草稿、同步动作。

改进点：

- 与 SEO Audit 共用任务详情组件。
- 用字段级状态显示 title、description、schema、内链、图片。

## 组件规则

- Button：主操作黑底白字，AI 生成冷蓝，发布/同步深黑或成功绿小按钮，危险红色只用于删除/拒绝，普通操作白底边框。
- Inputs：高度 36px，文本域最小 96px，字符限制字段必须显示计数。
- Tables：表头 sticky，行高 52-56px，缩略图 44-48px，状态芯片固定宽度。
- Drawers：右侧 520px 到 720px，适合产品详情、媒体审核、SEO 任务详情。
- Empty states：只给下一步操作，不写长说明。
- Progress：后台任务用小型状态条，展示 task id、当前阶段、可离开提示。
- Cards：只用于真实信息分组，不做卡套卡；普通分区尽量用线条和标题。
- Icons：线性图标，16px 或 18px；不要使用彩色 icon 背景圆。
- Motion：只保留 hover、loading、任务进度，不做弹跳和大动画。
